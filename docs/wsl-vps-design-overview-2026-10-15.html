NETWORK & IDENTITY · ARCHITECTURE REVIEW

一个公网出口，
不是一台相同的电脑。WSL → Windows Clash → 德国 VPS

将 WSL 的网络出口、解析链和应用环境统一到受控的德国 VPS 路径。Windows 是承载节点，不应成为目标网站看到的公网来源；但它并不会从本地硬件、内核与互操作环境中消失。

方案评估 · 尚未部署正式 EXE 0.5.9 / 同一核心TCP + UDP + 双栈需独立验收本轮未改变网络状态
01

数据与解析，必须分开设计

WSL / MANAGED SCOPE

原生应用与透明层

CLI、浏览器、Claude 子进程。不依赖代理变量；DNS、UDP relay、IPv6、启动拒绝直连一并设计。

本地权限边界须明确
WINDOWS / TRANSPORT

Clash 同核心固定入口

不经过普通分流或 DIRECT 回退；配置再生后仍保持。当前官方版本缺少原生持久自定义 listener，是首要可行性闸门。

不能直接复用旧维护器
VPS / EGRESS

核实的德国出口

客户端到 VPS 的 IPv6 ≠ 目标出站的 IPv6。按实际目标核验出口，地区归属冲突时不放行。

目标仅见 VPS 来源
AFTER VPS · TWO DISTINCT FLOWS

业务数据面

VPS 建立到目标服务的连接。公网来源查询应显示 VPS 出口；TLS、HTTP 与应用行为仍由具体客户端产生。

DNS 解析面

受管解析请求也经 VPS 到核实的非大陆 resolver；解析结果再用于连接。DNS 不是所有业务数据的串行下一跳。

禁止替代目标：普通 17890 + HTTP_PROXY、全 Windows GLOBAL、单次出口探针或“阻断一切”都不能单独证明完整接管。独立 WireGuard 直连和在 VPS 上运行程序是不同架构，不能悄悄替换本方案。
02

“看到的 IP”，其实有三层

PUBLIC IDENTITY

公网服务看到的来源

公网 curl / 接收端日志应为 VPS IPv4 或 IPv6，不是宿主网络的公网地址。必须覆盖无代理环境、UDP、IPv6 与动态目标。

可通过端到端网络设计验证。

LOCAL IDENTITY

本地命令看到的接口

ip addr 如实枚举当前网络空间。可评估独立 namespace，让普通负载只看到自己的回环与私有 TUN/veth，减少宿主接口暴露。

这不是赋予 VPS 公网地址，更不是伪造命令输出。

DEVICE IDENTITY

内核、硬件与应用特征

WSL 内核、WSLg GPU、字体、TLS栈、账号历史和机房 ASN 不会因代理自动改变。德国 IP 不保证平台判断为德国电脑。

一致性与最小暴露，不是完整复刻保证。

保留而非重建：Europe/Berlin 与 DST、既有 en-US 英语、浏览器 profile 和 Claude 数据。GeoIP 必须跟随核验后的实际出口；不要为迁移重装应用、随机化身份或修改 CC Switch。

04

先过可行性闸门，再谈部署

P1 / INVENTORY

实际盘点

统一实施者；备份后安排 WSL 观察窗口，核对旧服务、DNS、适配器与容器。

P2 / CORE GATE

固定入口

隔离验证同核心持久机制。原生支持缺口未解决，不迁移应用。

P3 / DATA PLANE

透明接管

验证 TCP、UDP、双栈、DNS、代理循环和 fail-closed 启动次序。

P4 / BOUNDARIES

身份与边界

稳定身份；独立处理 Docker、Windows interop、WSLg与工具子进程。

P5 / ACCEPTANCE

范围化验收

端到端关联证据、隔离故障验证、定向回退；不影响校园认证与 API。

安全通过 ≠ 功能通过

UDP 或 IPv6 被拒绝而没有泄漏，可以是安全降级；但对应功能仍未完成。不可用时直连回退则安全不通过。

不使用生产网络注入故障

不停止共享核心、不切断 DNS/网卡、不重建全局 NRPT。故障测试在隔离环境；每次实际网络变更前后验证关键网址。
