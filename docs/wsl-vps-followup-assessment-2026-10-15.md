日期：2026-10-15，Asia/Taipei。

本次用户要求是阅读并分析新增要求，不是授权部署。本文与两位只读子代理复核需求总纲、网络架构、身份模型、验收报告、GitHub 项目调查及离线图解；并核对本地官方 v0.5.9 配置生成与保护源码。没有启动 WSL/Claude、登录账号、访问外站、SSH、查询当前核心或修改网络。原报告中的运行状态和关键网址响应均为历史证据，本文不将其更新为当前状态。

## 1. 接续结论

新增需求不是简单的代理环境变量配置，而是同一 Windows Clash 核心下，WSL 普通原生 TCP/UDP 的透明固定出口、独立 DNS 政策、失败关闭与最小宿主信息暴露。

设计方向合理，但尚不具备直接迁移生产工作负载的条件。首要阻碍是同核心固定策略的受支持持久化，其后才是透明适配器选型。当前不能宣称 WSL 已完整纳管，也不能用此前 OpenAI/Claude 域名 IPv4 策略推导任意 WSL 目标均为德国 IPv4。

## 2. 已有本地源码支撑的硬限制

- `src/config.rs:361`、`:362` 清理自定义 listeners/authentication；`:366` 起将独立入口端口归零；`:375`、`:376` 固定关闭 LAN 并绑定 IPv4 loopback。直接往订阅或 runtime YAML 加入口，不能当作应用支持持久化。
- `src/claude_check/protection.rs:205` 起按指定目标增加保护规则，`:221` 起保留其余规则。原生 Claude 保护不是 WSL 全目标路由，普通 17890 也不是天然固定 VPS 的专属入口。
- 这些限制不证明所有同核心方案都不可能。架构报告方案 C 的源身份路径仍可研究，但 NAT/SNAT 后 metadata、overlay 顺序、宿主代发 DNS 和失败回退都尚需隔离验证。
- Mihomo 外链 API/热更新语义和候选项目功能本次未重新联网核查，沿用原调查的静态依据及限制；不能把公开版本字符串或 `force=false` 当作实际核心无副作用更新的保证。

## 3. 本次发现的五项文档与验收缺口

以下是设计阶段问题，不是已确认的运行泄漏。为保留用户新增材料，本次不改写原报告，在此记录后续应定向收敛的内容；原验收报告第 8 节“未发现剩余实质矛盾”仅代表当时的复审范围。

### 3.1 DNS 的 system 例外包含公网反向查询

架构报告第 4.2 节将相关规则概括为 private 名称解析，但 `src/claude_check/protection.rs:290` 把整个 `+.in-addr.arpa`、`+.ip6.arpa` 指向 system；两者也包含公网 IPv4/IPv6 的 PTR 查询，不仅是私网反查。

影响：若复用现有核心 DNS，不能只验证正向 A/AAAA 或看到境外 DoH 就回填 R04 通过。应在 VR-06/VR-07 补公网 PTR、私网 PTR、宿主委托解析及备用路径证据。源码仅能证明策略存在，不能证明本机已发出泄漏请求；本次不修改该规则，避免误伤宿主合法解析。

### 3.2 遥测信息最小化不能升级为任意应用保证

验收报告第 3.1 节把“不应从应用遥测得到宿主本地身份字段”写成必须守住的边界；身份报告第 3.5 节则正确说明：保留挂载、interop 或系统读取权限的程序仍可能主动上传真实字段，普通代理不能清洗端到端 TLS 内的内容。

应限定为受管权限与已审查字段的测试结论，分别记录应用网络路径和主动信息披露。不能以合成探针无泄漏证明任意 CLI/Electron 遥测均不含本地身份；不引入 TLS 中间人或关闭证书校验。

### 3.3 WSL 校园服务范围不应隐式扩大

总纲 R09 强制保护 Windows 日常通路，并将 WSL 校园私有服务列为待明确范围；身份报告第 6.1 节和 VR-01 的未来 WSL 基线措辞可能被理解为 WSL 也必须访问两个地址。

应先明确 WSL 是否需要校园服务及具体通路。Windows 的校园认证和 API 可用性仍是每次网络变更的硬门槛；不能为了让 WSL 校园测试通过，偷偷开放 LAN、宿主 DNS 或普通直连例外。若 WSL 不需要该服务，应记录不在范围，而不是把 Windows 保障要求删除。

### 3.4 DNS 通过条件须绑定境外解析服务证据

VR-06/VR-07 强调经 VPS、TLS 正常及不降级，但还须显式关联验收报告第 2.4 节关于运营方、实际服务点及递归上游可证程度的要求。请求经 VPS 不等于 resolver 一定在境外；未知 DoH 经 VPS 也不等于 R04 全部通过。

允许任意程序访问任意 HTTPS 目标时，无法普遍识别其加密协议内的自主解析。后续应约束受管应用/目的范围，或保留未证实项，不能仅凭封锁 53/853 宣称强制了所有解析器。

### 3.5 R06 缺少明确的普通模式与节点切换负例

VR-12 已列配置再生、原生保护和订阅更新，但应另外明确：普通 `rule/global/direct` 切换、普通组选择 DIRECT/其他节点，以及普通 profile 切换。

只在隔离副本验证：WSL 仍经固定 VPS，或因条件不满足而失败关闭；不得跟随普通模式或节点漂移。失败关闭不等于功能仍可用；若 R06 要求切换期间也保持可用，应将可用性另行判定，不能把拒绝连接计为完整功能通过。不得在用户活跃共享核心上进行这些负例。

## 4. 可实现目标与不能混称的目标

- 公网回显显示 VPS 出口是可验证目标；本地 `ip addr` 显示真实私有 TUN/veth 地址并不矛盾。netns/UTS 可以减少普通负载枚举宿主接口的机会，不赋予其 VPS 公网 IP，也不复制硬件/内核。
- 客户端经 IPv6 连接 VPS、VPS 经 IPv4 连接目标完全兼容。若所有目标都强制 IPv4，IPv6 字面量和 AAAA-only 目标可能失败；这只能算对应安全政策有效，不能算 IPv6 功能通过。
- 普通代理不创建任意 IP 互通的虚拟局域网。若 ICMP/任意三层协议必须成功，需要另行确认三层架构；不能悄悄以 WSL 直接 WireGuard/Tailscale 替代同核心要求。
- Linux OUTPUT 不自动覆盖 Docker Desktop daemon、容器转发和 Windows interop。只纳管一个 launcher 也不等于全部发行版进程已纳管。
- 德国出口、时区/语言一致、最小信息暴露可分项验证；完整复制 VPS 指纹、所有程序绝不上传本地信息、第三方永久认定德国均不可由普通代理保证。

## 5. 建议的实施前收敛顺序

1. **先确定范围和单一实施者。** 保留 R01-R13，明确全发行版进程/服务清单、Docker/interop/WSLg、WSL 校园服务及 IPv6/ICMP功能目标。受限工作区仅是阶段性试点，不擅自缩小最终范围。
2. **再解决同核心固定策略。** 优先评估官方支持入口；备选为可证明源身份的现有 TUN 路径。持久化、组成员、认证、重生和普通模式切换未通过隔离验证前，不迁移业务，不新增互相抢写的维护器。
3. **最后做透明层原型。** tun2proxy 可优先研究 namespace 集成，hev/tun2socks 作标准 SOCKS UDP 对照；实际只选一种。验证 UDP ASSOCIATE 返回地址/端口、双栈、MTU/回程、反循环、最小权限和退出后失败关闭，不能只测 TCP 或检查 UDP socket 存在。
4. **解析与生命周期单独验收。** 包含 PTR、bootstrap、冷缓存、dnsTunneling、应用 DoH、容器 DNS 与上游境外证据。`.wslconfig` 历史文件值不等于有效设置；其节名及当前版本行为须另核查。
5. **每步维护关键 Windows 通路。** 实施前阅读故障记录 12 与修复脚本但不例行执行；取得新的 DNS/TLS/HTTP 基线、紧邻备份和定向回滚，变更后复验。启动已停止 WSL 可能激活旧 systemd 服务，也须先安排窗口，不能当作完全无副作用的只读检查。
