## 3. 将目标转化为可验证要求

### R01 — 公网出口

WSL 中通过公网服务查询自身来源地址的请求，应由指定 VPS 的实际出口 IPv4/IPv6 发出，不出现宿主机校园/家庭/移动网络的公网地址。必须覆盖代理环境变量清空、不同客户端和目标；不能只证明一次 curl 使用代理成功。

### R02 — 透明接管能力

对受管 WSL 内的普通原生进程，TCP/UDP 不应依赖应用自行遵循代理变量。TCP 和 UDP 功能成功、无直连泄漏分别验收。阻断 UDP 可以是临时安全降级，但不算“完整接管 TCP/UDP”通过。ICMP 等其他协议单独定义，不假定 HTTP/SOCKS 能承载任意 IP 包。

### R03 — IPv6

处理 IPv6 字面量、AAAA-only、双栈竞速、链路本地与公网路径。若 IPv6 暂不能满足地区/路由条件，应在 WSL 范围失败关闭并如实标为功能未完成；不得全局关闭 Windows IPv6 代替设计。

### R04 — DNS

受管工作负载的公共名称解析及其 DoH/DoT 传输，经受控 VPS 路径访问核实的非大陆解析服务，不经校园/宿主备用解析路径回退。引导解析、fake-IP、私有名称、应用内 DNS 与 Docker DNS 分开记录。resolver 的 anycast 地址或“加密”字样不能证明请求实际经 VPS、物理节点在德国或上游完全不涉及大陆。

此要求有独立的应用信任边界：若允许任意不可信程序向任意 HTTPS 服务发送数据，它也可能在加密应用协议里自行完成名称解析；普通代理不能在不解密 TLS 的情况下普遍识别并证明每个 resolver 的地点。仅限制53/853或已知DoH主机不足以保证“只使用指定境外解析器”。后续须对受管应用约束自定义解析、采用经审查的目的允许策略，或明确记录无法证明的路径，不能把“所有连接经VPS”偷换成“所有解析服务均在境外”。不以HTTPS中间人或关闭证书校验消除这个限制。

### R05 — 失败关闭

核心未就绪、节点失败、透明转发器退出、配置重生、断线恢复等情况下，受管 WSL 不退回本地公网出口。阻断范围限定为受管工作负载，不以切断普通 Windows 联网为代价。普通 Linux 规则不应被描述成可防御宿主管理员或 WSL root。

### R06 — 同核心与持久化

使用正式 Clash of Rust 管理的同一个核心，不启动旧 XUAN VPS Mihomo。WSL 专用路径固定到已核实 VPS；普通代理模式/节点选择、配置重生或应用重启不能悄然改变该路径。控制者唯一，不能由两个定时维护器互相覆盖。

### R07 — 设备环境一致性

保留已有浏览器/Claude 身份资料，定义 Europe/Berlin 时区及 DST、语言、定位和网络出口一致性。区分真实硬件/内核属性、可配置的应用环境及网站可观察信号。不得把“完整复制 VPS 硬件或保证平台认定德国”当可交付保证。

### R08 — 容器与跨系统边界

Docker Desktop daemon、容器 bridge/host-network、特权容器、Windows interop、WSLg、工具启动子进程、动态 MCP/插件目标分别纳入范围或明确不支持。不能因它们由 WSL 中的 CLI 启动就认为其流量自然经过 Ubuntu 防火墙。

### R09 — 不可破坏的 Windows 网络

校园认证 `https://ipgw.neu.edu.cn/` 与 API `https://api.okinto.com/` 保持 Windows 日常通路 DNS、正常证书验证和 HTTP 可用。每次实际网络改动前后验证并备份；禁止全局 NRPT 虚拟 DNS 锁定、全局 Dnscache 封锁、清空网络规则及生产故障注入。用户在后续明确：WSL 不需要访问校园服务，该访问不作为 WSL 验收要求，也不为此增加校园网、局域网或宿主 DNS 直连例外。Windows 的关键通路保障不受此范围澄清影响。

### R10 — 无目标业务在线测试

本次分析不启动或登录 Claude，不运行其 CLI、Desktop 或检测页，不执行模型请求。后续网络验收优先采用自有/获准中立接收端；访问真实业务目标仍须遵守另行授权及实际出口门槛。

### R11 — 本地 CLI 可见性

公网来源查询与本地网卡枚举是两种不同操作。公网 `curl` 应看到 VPS 出口；`ip addr`、`hostname -I`、路由查询反映真实本地/虚拟接口，代理不会将其自动改成 VPS 公网地址。不得替换这些命令输出制造“已隐藏”的假证据。若要求本地程序也无法获得 Windows 信息，应采用受限工作负载边界并验证；若要求真正拥有与 VPS 互通的虚拟子网，需要额外三层隧道，而不是将普通代理说成局域网。

对“不要枚举到 Windows 镜像接口上的本机地址”的可达成部分，主方案应评估独立网络命名空间：普通工作负载真实看到自己的回环和私有 TUN/veth，而不直接进入发行版的 mirrored 网络命名空间。它减少接口信息暴露，不伪造命令，也不等于接口拥有 VPS 公网地址；helper权限、namespace切换、挂载、Windows interop及WSLg仍须分别约束。

### R12 — 记录与实施边界

将原始要求、证据、完整主方案、候选方案、风险、不可保证项、实施阶段、回退及验收写入本目录，允许后续会话接续。不把文档完成等同于运行目标完成；本轮不部署。

### R13 — 德国地区及实际目标路由

端点在德国、客户端到 VPS 使用 IPv6、目标最终出口为 IPv4/IPv6 是三个不同事实。必须核验目标实际出站和地区库一致性；有冲突的 IPv6 不能因为来自同一 VPS 就作为“德国出口”放行。已知域名规则不等于任意未来目标或共享服务均受覆盖。

## 5. 架构语义：Windows 隐藏与 DNS 不是一回事

### 5.1 数据面

目标数据通路是：WSL 受管工作负载，经 WSL 内透明接管层，到 Windows 上 Clash of Rust 的固定 VPS 入口，再由既有加密节点协议送至 VPS；VPS 重建目标连接，目标看到 VPS 的出站地址。

“Windows 隐藏”应定义为目标连接的来源不是 Windows 本地公网出口，而不是互联网中不存在 Windows 这一物理转发节点。接入网络仍能看到本机与 VPS 的连接，VPS 仍能看到客户端对它的连接；代理不提供对宿主管理员、运营商或 VPS 管理者的绝对匿名。

连接源地址受控也不等于应用不能泄露本地信息：若程序能读取本地接口、挂载目录或 Windows 环境，它仍可能在 HTTPS 请求正文、请求头或遥测中主动发送这些字段。普通加密代理无法代替应用权限隔离与数据最小化；不为此引入 HTTPS 中间人解密、伪造证书或跳过 TLS 校验。

### 5.2 解析面

DNS 是建立目标连接所需的并行解析链，不是全部业务流量经过的下一跳。正确模型为：业务数据经 VPS 到目标；需要解析时，受管 DNS 请求也经 VPS 到核实的外部 resolver，返回结果再用于连接。把 DNS 画成 VPS 与目标之间的串行代理会掩盖解析泄漏与应用内 DoH 旁路。

### 5.3 真正“局域网”语义

普通代理能实现共同公网出口，但不创建 WSL 与 VPS 之间可任意 IP 互访的子网，也不会把 VPS 公网 IP 赋予 WSL 接口。若用户最终需要三层虚拟局域网、ICMP 或任意 IP 协议，需要明确增加三层隧道及其在 Clash 链中的承载方式；独立 WireGuard 直连、远程桌面或直接在 VPS 运行程序是不同架构，不能不经确认替代本目标。

### 5.4 本地通信与“全流量”的边界

WSL 到本机代理、GUI 的本地 IPC、隧道维护和必要链路控制并不会全部送往公网目标，且是架构成立的前提。方案必须列明每个允许的本地端口/Unix socket、调用者与用途；不能将“本地所需通信”扩大成所有127/8、整个LAN或任意Windows服务均可访问。

R02 的透明功能与 R01 的公网出口保证针对受管工作负载的网络请求；本地必要控制流量作为精确列明的例外，不冒充经过VPS。若用户要求连本地接口枚举、ARP/NDP或所有本地IPC都不存在，那不是现有WSL宿主承载架构能保证的目标，应明确提出架构冲突，而不是通过删掉测试项缩小范围。

## 6. 决策结论与实施闸门

### ADR-01：保留“同核心、WSL独立、固定VPS”的主目标

主方案不是把 WSL 指向普通 17890，更不是将全 Windows 改为 GLOBAL/MATCH 以凑出结果。需要一个不会随普通规则或节点选择变化的受管入口，或经过隔离实验证明可靠的 WSL 独立流量身份和规则。应保留其他 Windows 应用及校园认证的既有能力。

### ADR-02：不把当前版本的持久化缺口藏在辅助脚本里

官方 0.5.9 的配置生成器主动删除自定义 listeners/authentication；旧辅助维护器又拒绝 live TUN 重载，当前原生保护依赖 TUN。不能复制旧维护器、仅改路径并定时覆盖配置来宣称稳定支持。

先在隔离环境评估同核心固定入口的受支持实现方式。若需要官方功能、单一受审辅助控制器、版本升级或源码更改，应逐项明确依赖与授权；本轮不改源码、不升级、不停止核心。未通过这一闸门时，完整运行目标仍未实现，不能先迁移现有应用。

### ADR-03：透明层和隔离边界必须成套设计

独立 WSL TUN-to-SOCKS 等候选只负责将包转换为代理请求，不天然解决 DNS、IPv6、UDP relay、Windows interop 和 Docker。转发器不能自行重开直连；上游、控制通路和普通目标必须分离，防止代理循环及启动窗口。

### ADR-04：身份一致性优先于“复制所有指纹”

保留 Europe/Berlin 和既有 en-US，而不是批量随机更换浏览器身份或伪造 Linux 命令输出。VPS 通常是无桌面的 Linux 服务器，本地 WSLg/Windows 浏览器不是同一种设备；一致、最小暴露、实际出口合格才是可验证目标。IP地区库、ASN、账号历史和平台判断不在代理可完全控制范围内。

### ADR-05：安全降级不冒充功能完成

代理未就绪时拒绝外网是安全目标；UDP/IPv6 被阻断而无泄漏仍是相应功能未完成。报告必须分别给出出口保密、安全失败和功能覆盖三种结论。
