## 已确认问题

### 1. [P1] 完整恢复读取错误的快照字段

位置：`scripts/wsl-secure-egress/WslSecureEgress.psm1:1780–1783`。

正常安装的 journal 只有 `before_persistent_settings`，`Read-WslEgressState` 又将对象递归转换成 OrderedDictionary。这里使用 `PSObject.Properties` 检查字典键会得到假，随后读取不存在的 `before_settings`，在 StrictMode 下抛错。因此正常安装后的 `Rollback/Uninstall -RestoreOriginalNetwork` 在恢复 Linux、`.wslconfig` 和 Hyper-V 设置之前失败。应使用已有字典取值函数。纯内存 PowerShell 复核确认 `Contains=True`、属性检查为假、访问旧字段抛错。

### 2. [P1] 另一发行版启动会误阻断共享网络

位置：`scripts/wsl-secure-egress/linux/manager.py:663–665`、`:1543–1549`。

manager 已建立合法共享 nftables 表后，另一受管发行版的 boot hook 用自身 `distro-config` journal 验证该表。其 journal 使用独立 owner，且没有 manager 的 root 表哈希，所以合法共享表被分类为 unknown，随后安装独立 emergency OUTPUT/FORWARD deny，阻断原有受管 WSL 流量。需要跨发行版可验证的共享规则身份；现有直接 mock 分类结果的测试没有覆盖真实识别链。静态确认，未在生产启动第二发行版复现。

### 3. [P1] 显式包更新的清单调用链不可用

位置：`installer/clash-of-rust.nsi:313`；`scripts/wsl-secure-egress/Upgrade-Package.ps1:423–434`、`:225`、`:278`。

安装器 `/UPDATE` 未传 `ManifestPath` 与 `ExpectedManifestSha256`，脚本直接拒绝 Apply。使用相同缺参方式、安全的不存在临时路径复现 exit 1，消息为要求私有清单与精确 SHA256；在任何安装/服务变更之前返回。

即使补齐参数，入口还会把清单解析对象 `$approved` 传给要求清单文件路径的 `[string]$ApprovedManifest`，随后在绝对路径校验处失败。纯内存复核得到 `An absolute package path is required.`。需要同时修复安装器传参与脚本对象/路径契约，并覆盖真实入口的离线测试。

当前 fork 的 `SELF_UPDATE_ENABLED=false`，因此不是当前 UI 自动下载的触发路径；影响显式 `/UPDATE` 和 Windows 安装包升级 CI。缺参问题已有 GitHub 未解决审查意见，本轮确认仍存在。

### 4. [P2] 多发行版安装中断后遗漏恢复对象

位置：`scripts/wsl-secure-egress/WslSecureEgress.psm1:1184–1195`、`:1788–1793`。

已修改的发行版只加入局部 `$configured`，直到全部 configure、terminate 和 shutdown 成功后才持久化。后续任一步失败时，journal 的 `distro_configs` 仍为空，恢复跳过已经修改 DNS/interop/boot 配置的发行版；其 Linux journal 还会拒绝再次 configure。应在可能修改每个发行版之前写入待恢复清单，逐项记录进度。静态确认，未进行生产故障注入。

### 5. [P2] 旧服务回滚信任可替换 journal 并绕过服务白名单

位置：`scripts/wsl-secure-egress/linux/retire-legacy.py:86–99`。

工具允许 journal 放在项目忽略备份目录，但回滚不验证文件/父目录所有权与权限，也不限制 journal 条目的服务名属于 `UNITS`。若普通用户可替换 journal，未知服务加 `sha256:null` 会与缺省 inventory 的 None 相等，通过验证，继而让 root 执行该服务的 `systemctl enable`。需要受保护的 journal 路径、固定服务白名单和严格摘要类型检查。静态确认，未运行旧服务工具。

### 6. [P2] 旧服务退役中断后回滚再次失败

位置：`scripts/wsl-secure-egress/linux/retire-legacy.py:93–96`、`:114–126`。

原 APT override 不存在时，日志预先记录 created=true，但文件到 disable/stop 结束后才创建。中间失败可能已经停用部分服务，回滚却先读取不存在的 override，抛错而不能恢复服务。回滚删除 override 后若再失败，重试也有相同问题。应允许尚未创建或已经撤回的本轮文件，并记录恢复进度。静态确认。

### 7. [P2] 恢复后重装早期失败会使桌面状态互锁无法恢复

位置：`scripts/wsl-secure-egress/WslSecureEgress.psm1:1592–1610`；`crates/client-core/src/wsl/state.rs:126–130`。

桌面已观察到非零 generation，完整恢复后再次安装：broker 先归档并移走当前 journal，再读取新 profile。若 profile 丢失等早期校验失败，下一次无 journal 的 Status 返回 generation 0，Rust 无条件判为 GenerationRegressed，无法通过状态刷新清除失败操作互锁。应在移走旧状态前完成输入校验，并为已确认结束的部署定义安全的 generation 生命周期边界。静态追踪确认，未执行重装。
