## 1. 先确定“像 VPS”究竟指什么

可实现的核心目标是：在明确的进程与协议范围内，外部服务看到已核实的德国 VPS 出口；DNS、时区和应用语言等可控设置保持一致；代理失效时拒绝直连；不向外发送不必要的本机信息。

这不等于把本地 WSL 变成那台 VPS，也不等于复制它的完整设备身份。不能承诺“所有命令、所有协议、所有应用、任何权限下都只呈现 VPS 信息”，更不能保证第三方账号、区域政策或风控接受。隐私和配置一致性不是规避服务规则的保证。

必须分别记录四层事实：

1. **本机观测层**：Linux 内核、网卡、路由、主机名、文件系统和 Windows 宿主提供的真实信息。
2. **传输出口层**：某次 TCP/UDP 请求、DNS 查询实际走哪条链，以及目标看到的公网源地址。
3. **应用声明层**：语言、时区、浏览器 API、权限、代理环境和应用主动上传的字段。
4. **服务侧历史层**：账号注册/付费区域、cookie、设备标识、登录历史、IP 信誉和行为相关性。

只能逐层评估，不能用一个 IP 查询页的德国结果替代其他三层。

## 2. 公网出口与本地地址：不可混淆的物理限制

### 2.1 不同命令实际回答不同问题

- 获准的公网 HTTPS 回显服务：报告该请求到达服务端时的源地址。经过代理时通常是 VPS 出口；只证明那次请求和那条路径，不证明 DNS、UDP 或其他应用。
- `ip addr`：通过 Linux netlink 查询本网络命名空间的接口地址，可能包含 WSL 虚拟/镜像接口、回环、容器和 TUN 地址。HTTP/SOCKS 代理不会重写这些接口。
- `hostname -I`：枚举本机接口地址；不是查询公网 NAT/代理出口。它继续显示 WSL 地址属于正常现象，不是单独的泄漏证据。
- `ip route`、`ip route get`：说明 Linux 路由选择，不完整呈现 Windows TUN、代理内部路由及 VPS 出站策略；仅靠它们也不能证明最终出口。
- `hostname`、`uname`、`/proc`、`/sys`、环境变量和挂载信息：仍属于当前 WSL 内核、虚拟硬件、用户空间及宿主集成，不因出口德国而变成远端机器。
- 经 interop 调用 Windows PowerShell、`ipconfig.exe`、Windows DNS 或 `curl.exe`：查询或联网的是宿主 Windows。Linux OUTPUT 过滤不能把它们算作已受控的 WSL 原生请求。

不建议给 `ip`/`hostname` 写 alias、包装器或伪造输出。这样既不会改变内核与实际流量，又会破坏诊断、脚本和审计；可绕过包装的程序仍可读取真实接口。

### 2.2 如果要求本地“常驻 VPS 地址”

地址是接口与路由的属性，不是代理软件的显示偏好。给 WSL 随意添加 VPS 公网地址，不会获得该地址的路由所有权，反而可能冲突、丢包或错误宣告来源。

不同架构必须明确范围后另行设计：

- **WSL 内三层 VPN/TUN**：为 WSL 分配隧道地址，经 VPS 路由/NAT 出网。公网出口可为 VPS，但 `ip addr` 通常仍含 WSL/回环及私有隧道地址；不是“只显示 VPS 公网 IP”。HTTP/SOCKS 入口也不自动成为任意 IP 协议隧道。
- **专门路由的公网前缀/地址**：只有提供商授权、VPS 转发、回程与防火墙全部正确时才可交付给下游接口。通常需要额外地址或前缀，不宜把 VPS 正在使用的单个地址直接复制到 WSL；仍不能消除本地硬件、内核与其他接口。
- **独立 VM**：可改善 Windows interop、挂载和图形共享边界，但内核与虚拟设备仍是 VM 的，不会自动等于 VPS；网络仍需独立设计。
- **远程执行于 VPS/专用远程 VM**：命令真正读取远端内核与接口。这最接近“命令看到 VPS”，但用户文件、浏览器/GUI、密钥、账号及运维风险转移到远端，且远端自己的私网/回环地址仍会存在。不能未经授权迁移资料或账号。

如果坚持所有本地 CLI 输出都与远端一致，必须先修改目标描述；保持本地执行、Windows 全功能互操作并同时要求其无从读取本地信息，在权限模型上互相冲突。

### 2.3 具体候选：受管工作负载的真实 namespace 视图（R07/R08/R11）

对于不需要宿主网络管理权限的普通 CLI/应用，可以评估独立 **network namespace + UTS namespace**：不把 WSL mirrored 接口和宿主相关全局 IPv6 接口移入该 namespace，仅提供其真实的 `lo` 和私有 TUN/veth 等受控接口，并为该 UTS 设置独立主机名。这样 `ip addr`、基于接口枚举的 `hostname -I` 等正常读取的是受管 namespace 的真实网络状态，而非把宿主接口输出替换成假值；可具体减少这些命令看到 mirrored 接口/宿主相关全局 IPv6 的机会。UTS 主要隔离 hostname，不把内核或所有系统信息一起隔离。

这不是赋予 WSL VPS 公网地址，也不等于所有信息都不可获取：私有 TUN/veth 地址仍应如实显示，公网回显是否为 VPS 取决于实际转发链；内核、硬件、挂载、环境、其他进程信息及 Windows interop 不会仅因 netns/UTS 消失。若仍可读取宿主挂载、调用 Windows 程序或通过其他 IPC 询问宿主，仍可能取得并上传这些地址/标识。

实施前必须单独设计并验收以下条件，不在本文部署：

- 受管进程及全部子进程/后台服务如何进入该 namespace；谁拥有特权 helper、转发器和 namespace 句柄；隔离运行 UID、最小 capability，并防止普通负载自行进入 host namespace、修改路由或开启直连。具备相关 root/capability 或可访问并进入 host namespace 的主体不受这项普通负载保证。
- namespace 内的 DNS、IPv4/IPv6、TCP/UDP、默认拒绝和启动顺序，以及 helper 自身上游如何只连接同核心固定 VPS 入口、避免回路。私有 veth 连到默认宿主转发并不天然失败关闭；网络视图变窄也不证明 R02/R03/R04/R05 已通过。
- Windows loopback 代理在独立 namespace 中不一定仍可经原 `127.0.0.1` 访问；12345/18001、认证回调、IDE、共享目录、Docker、WSLg 的必要 socket/端口/代理桥应逐项限定，不能为方便把宿主网络或全部 IPC 重新暴露。
- 如需进一步限制其他信息面，再评估 mount/PID 等边界和最小共享；不要假设新建 netns 自动隐藏 `/mnt/c`、`/mnt/wslg`、9p/DrvFS 或宿主进程信息。共享范围与 GUI/输入法/音视频/文件工作流的可用性影响需用户明确接受。

可验收口径是“指定普通工作负载的命令显示该受管 namespace 的真实、最小网络/主机名视图，且外部 TCP/UDP 按 R02 经 VPS”，不是“全部 CLI 与远端 VPS 完全相同”。本候选补充了本地可见性的可实现部分，不降低 R02 的最终透明 TCP/UDP 目标；root/宿主权限防御仍归 Scope R，实施与隔离故障验收另行授权。
## 3. 德国身份一致性：哪些能调，哪些不能保证

### 3.1 出口、地区库、ASN 和双栈

- 本机至 VPS 使用 IPv6，与 VPS 至目标使用 IPv4 是不同段；前者本身不代表目标看到了本机 IPv6。
- 每一种实际目标通路都要核对出口。某组已固定、某个域名走 IPv4，不代表共享遥测、第三方 provider、MCP、下载器或直接 IP 请求相同。
- IP 地区库、ASN 注册信息、提供商名、数据中心属性和历史信誉可能冲突。HTTP/SOCKS 代理不会把数据中心 ASN 变成住宅 ISP，也不能统一所有第三方地区库。
- 已记录的 VPS Claude/OpenAI IPv4-only 规则只覆盖明确列出的匹配器。未知目标不能借用其结论；本轮未重新联网证明出口。
- 之前记录过 IPv6 地区库冲突，见[交接第 13 节及后续修正](local-network-handoff-2026-10-15.md)。未来冲突、未知或路由变化时，应将地区门槛标为失败/未确认，而非挑选一家德国结果放行。

### 3.2 时区、时钟、语言与地区格式

- 现有设计保留 `Europe/Berlin`，使用 IANA tzdata；冬季 CET 为 UTC+01，夏季 CEST 为 UTC+02。2026-10-15 柏林按通常规则处于夏令时，不能全年硬编码 GMT+1 或单一偏移。
- 时区不是修改系统绝对时间。保证时钟同步和证书时间有效，不通过改 UTC 时间“模拟德国”。浏览器、Electron/Node、shell 和 systemd 用户服务可能使用不同环境，需分别检查。
- 原设计语言是 `en_US.UTF-8` / `en-US,en`，不是 `de-DE`。英语用户使用德国服务器是正常组合，不需为了表面一致擅自改为德语。
- `LANG`、`LANGUAGE`、`LC_ALL`、`LC_TIME`、`LC_NUMERIC` 与浏览器 Accept-Language 各有用途。`LC_ALL` 会覆盖其他 locale 类别；仅设置 `LANG` 不证明所有子进程一致。变更可能影响日期解析、排序、构建和脚本，保持现状优先。
- 时区/语言不能证明人在德国，也不能修正账号区域、用户手动输入内容或服务器已有的历史记录。

现有语言与字体事实来源：[语言归档](../../XUAN_VPS/docs/archive/2026-10-06-wsl-claude-language.md)，第 9-12 行；系统时区设置：[安装器](../../XUAN_VPS/scripts/configure-wsl-claude-de.ps1)，第 84-88 行。以上是历史设计证据，尚不是本轮 Linux 实测。

### 3.3 浏览器、位置权限与图形指纹

- **WebRTC**：候选地址与 UDP/STUN 是单独路径，不能用 HTTPS 代理出口替代验证。现有 Camoufox 禁用 WebRTC；若应用需要实时音视频，应重新评估最小功能与网络边界，不能直接全开。
- **Geolocation**：IP GeoIP、浏览器 Geolocation API、Windows Location/GeoClue 和用户授权的定位是不同来源。拒绝真实位置权限能减少披露，但不会自动让所有 API 返回德国；固定坐标也不证明真实位置。
- **Canvas/WebGL/字体/音频/屏幕**：可反映渲染栈、字体安装、GPU、缩放、显示器和图形环境。德国 IP 不改变这些；浏览器缓解也不覆盖 Electron、原生 CLI 或任意文件读取。
- **WSLg**：图形、音频、输入法和 GPU 可与宿主集成。禁用/隔离它可能破坏 GUI、音视频、硬件加速、复制粘贴和中文输入，不能作为无成本的“指纹清理”。
- **Camoufox**：当前启动器选择 `os="windows"`、`locale="en-US"`，用固定 `EXIT_IP` 推导 GeoIP，禁用 WebRTC、HTTP3和直接回退。实际进程仍是 Linux 浏览器；网页平台声明不等于底层 OS 被改变。与 TLS/字体/图形组合是否一致，必须观察而非凭参数推定。
- **资料与身份稳定性**：保留 profile、cookie、历史、字体和配置，不重建浏览器身份。`persistent_context=True` 主要保留 profile 数据；当前启动器未显式持久化完整生成指纹，不能承诺每次启动所有 canvas/WebGL 等值完全相同。不要反复启动目标去验证这一点；未来获准时用中立本地测试页比较必要字段，不收集完整高熵指纹到公开文档。

精确实现：[Camoufox 启动器](../../XUAN_VPS/scripts/wsl/launch-camoufox.py)，第 14-16、34-79、81-95 行；[浏览器策略](../../XUAN_VPS/browser/policies.json)，第 43-60 行；[Camoufox 边界说明](../../XUAN_VPS/docs/WSL-Camoufox.md)。固定 EXIT_IP 应与获准测试的真实出口核对，本文不记录地址本身。

### 3.4 TLS、HTTP/2 与传输特征

- 常规 HTTPS CONNECT/SOCKS 隧道内的目标 TLS 通常仍由本地应用创建。JA3/JA4、TLS 扩展、ALPN、HTTP/2 SETTINGS/头部行为、浏览器版本和 SDK 栈不会因为出口地址改变而自动等于 VPS 上另一客户端。
- VPS 重新建立对目标的 TCP 连接时，目标侧 TCP/IP 参数通常来自代理/VPS 网络栈，但这不意味着加密的应用层 TLS 指纹同时改变；若使用三层隧道，TCP 栈归属还可能不同。
- 代理协议在本机与 VPS 间的 TLS/Reality 特征不是目标网站一定看到的 TLS 特征。必须明确测的是哪一段。
- HTTP/3/QUIC 是 UDP；旧 HTTP CONNECT 通路及 `udp:false` 入口不承载任意 UDP。禁用 HTTP3可收敛浏览器路径，但不代表所有程序都改用 TCP。
- 不建议为“复制 VPS 指纹”进行 TLS 中间人解密、关闭证书校验或替换浏览器/SDK TLS 栈。它们会增加凭据与完整性风险，也无法保证服务侧判定。

### 3.5 原生 CLI、路径、账号和遥测

必须区分“目标连接看到的公网源地址”与“应用主动提交的内容”。CLI 或具备终端工具的应用可以读取用户名、hostname、网卡/本地地址、`/proc`、CPU/GPU、WSL 标识、挂载、Windows 路径、环境变量和工作区文件。应用若把这些字段写入 HTTPS body、加密 header 或遥测，出口德国仍会传出真实字段。常规代理既不会自动理解这些字段，也不能在不终止端到端 TLS 的情况下任意清洗它们；不得通过 MITM 解密或关闭证书校验实现所谓“全信息隐藏”。对保留 Windows 挂载/interop 读取权限的工作负载，不能保证其永远不知道或不上传宿主信息（R07/R08/R11）。

允许最小化不必要的遥测、权限和环境传递，但必须按应用支持的配置及功能影响审查。不能承诺“禁用遥测后没有其他上报”，也不应删除已有聊天、认证、keyring、项目历史或 CC Switch 数据来制造新身份。cookies、账号历史、付费/手机号区域、时段、访问节奏、时延、语言输入和行为相关性可能持续存在；网络配置不抹除它们。

静态端点审计仅定位可能地址，不证明实际上传字段或运行连接：[Claude 离线网络报告](claude-app-static-network-audit-2026-10-15.md)，第 5-7 节。本文不启动应用或读取账号存储来补充这些信息。

## 4. 现有 WSL 网络与隔离边界

### 4.1 历史实现，不冒充当前 Linux 状态

1. 登录 shell 的代理变量指向认证 `127.0.0.1:18001`；非登录进程/systemd 服务不一定继承。见[旧安装器](../../XUAN_VPS/scripts/configure-wsl-claude-de.ps1)，第 62-79 行。
2. DNS 使用 `127.0.0.2:53`，本地转发器固定 TCP 上游 `127.0.0.1:1053`；Python 自身不执行 DoH。见[DNS 转发器](../../XUAN_VPS/scripts/wsl/xuan-doh-forwarder.py)，第 5-23、52-57 行。
3. OUTPUT 拒绝非回环 IPv4/IPv6 TCP/UDP 和旧 `7890`，但允许其他回环服务及其他协议。它不是“只有 18001 能访问”的默认拒绝白名单，也不是透明转发。见[WSL 防火墙](../../XUAN_VPS/scripts/wsl/xuan-claude-de-firewall)，第 25-42 行。
4. Camoufox/Claude Desktop 的历史入口是本地 `12345` 适配器，其实际实现、上游认证及启动顺序未在本轮 Linux 读取。不能假定它已迁至 Clash of Rust。
5. Docker 客户端代理使用 Windows 主机 `18001`；Docker Desktop VM 的 `DOCKER-USER` 辅助规则另管 bridge 转发。daemon 拉取、host-network、特权容器、Docker socket 和恢复窗口并未完整覆盖。见[Docker 防火墙](../../XUAN_VPS/scripts/wsl/xuan-docker-firewall)，第 61-81、119-129 行及[历史限制](../../XUAN_VPS/docs/WSL-Claude-DE-全流量.md)，第 33-41 行。
6. 防火墙 oneshot 在 `network-online.target` 后启动，且停止服务会撤销其规则；现有实现不能证明开机先于所有外向请求生效或遭停用后仍封闭。见[WSL service](../../XUAN_VPS/scripts/wsl/xuan-claude-de.service)，第 3-8 行。

本轮较早 Windows 只读观察中 18001/1053 未监听、WSL 为 Stopped；它只支持旧依赖失效风险，不能说明 Linux 文件已删除，也不是本轮最新基线。[迁移检查](../../XUAN_VPS/docs/14-WSL-ClashOfRust-migration-audit-2026-10-15.md)保留了当时证据及入口缺口。

### 4.2 当前应用不能靠加 YAML 自动补齐

官方 v0.5.9 生成器移除 `listeners/authentication`，其他入站置零，强制本机绑定并关闭进程发现。见[配置生成器](../src/config.rs)，第 352-380 行。原生保护为目标域名追加单节点保护路线，不是按 WSL 发行版识别的全流量规则，见[保护实现](../src/claude_check/protection.rs)，第 180-239 行。

同文件第 253-290 行显示国外 DoH 经保护路线，同时节点 bootstrap 与私有名字存在独立解析逻辑；不能用“有国外 DoH”宣称每一 DNS 包都经 VPS。入口持久化、重载安全和 DNS 必须由管理当前核心的会话一起设计；本文不授权启动旧维护器或新增第二套核心。

## 5. 分级承诺：普通原生流量与 root 防御不能混称

### Scope N：普通 WSL 原生进程的外向流量

可选过渡阶段可以明确为：指定发行版、指定非特权用户与服务产生的外部 TCP/DNS 经固定 VPS；尚未支持的 UDP/IPv6 失败关闭；回环/IPC/WSLg 等本机通道明确列例外。这只能降低迁移期直连风险，不能作为最终完成或缩小用户目标。R02 最终要求普通原生流量的透明 TCP 与 UDP 均成功经固定 VPS；相关 IPv6 行为按 R03 完整验收。仅在用户明确变更需求后，才能将 UDP 拒绝降格为最终设计；ICMP 等任意 IP 协议另行确定范围。

“All native ordinary”必须说明：是否包含 IPv6、UDP、ICMP、容器转发、包管理后台服务，以及开机/恢复窗口。只有完整列出范围并逐项验收后，才能用这个标签。代理变量本身不构成该范围的强制策略。

### Scope H：限制宿主旁路与信息读取

在 Scope N 外，还要评估 Windows interop、Windows 盘、宿主代理、DNS stub、VS Code Remote、Docker socket和GUI通道。这是另一项可用性与隔离项目，不应自动实施：

- 禁用 interop 会影响 Windows 程序启动、浏览器/OAuth 跳转、编辑器桥接、`code`/`explorer.exe`、Windows 侧工具与部分 Git credential helper。
- 禁用 `/mnt/c` 等自动挂载或限制 DrvFS/9p 相关共享，会影响跨盘工作区、资料访问和构建；并不自动撤销已开启的共享句柄、其他挂载或宿主控制权。
- mirrored 回环/宿主可达性可能同时服务代理、GUI/IDE及认证回调。对全部 loopback 的封锁可能让 12345/18001、OAuth、WSLg依赖和开发服务一起失效。WSLg通常还使用 `/mnt/wslg`、Wayland/X11/Pulse socket等通道，不能用一条 TCP 端口规则声称隔离整个图形栈。
- 只按端口拦截 9p、WSLg或interop不足以证明文件/IPC隔离；必须按实际 WSL 版本和通道盘点。不要关闭 Windows 全局网络服务或全系统 DNS来补齐范围。
- 更强边界通常需要独立 VM/远程环境与最小共享权限。若仍要求无缝访问 Windows 的文件、进程和应用，应接受这些宿主信息可见的残余风险。

### Scope R：对 root/管理员或恶意特权程序防御

WSL 内 root、具有 CAP_NET_ADMIN/CAP_SYS_ADMIN 等能力的进程、可运行特权容器或控制 Docker daemon 的用户，可能修改规则/路由、建立命名空间或读取超出普通用户的资料；Windows 管理员还可控制 WSL 宿主。root 不必然能突破任何外部强制隔离，但本发行版自己维护的 iptables 不能作为对 root 的完整信任边界。

若要抵御这些主体，执行与强制策略应移到其权限之外，并限制共享、capability、Docker socket和宿主权限；需要单独威胁模型和运维设计。不能让 root 管自己的拒绝规则却承诺它无法绕过。普通用户若可无密码 sudo或访问Docker socket，也不能被当作没有这些能力。

## 6. 可验收身份基线与失败状态

以下是后续获准窗口的验收设计，不是现在执行的命令清单。只用中立获准端点/本地测试页，不启动 Claude，不进行账号登录、模型调用或完整第三方检测。禁止收集完整环境、认证 URL、原始用户资料或完整高熵指纹到共享记录。

### 6.1 建议记录的最小基线

1. **范围声明**：发行版/WSL版本、网络模式、用户/服务权限、Scope N/H/R、TCP/UDP/IPv6/ICMP支持矩阵、明确例外与验收时间。
2. **关键网络**：Windows 主机日常通路访问校园认证与 API；域名解析、正常 TLS 校验及 HTTP 语义。改动前、每一步后、回退后复核，不用绕开原通路制造通过。用户已明确 WSL 不需要访问校园服务，不将校园可达性列入 WSL 验收，也不为其增加校园直连例外；WSL 的 API 等获准公网目标仍按受控 VPS 通路验收。
3. **出口证据**：固定入口归属、同核心路由链、与中立请求对应的实际出口；IPv4/IPv6分别验证或明确禁止。共享域/直连IP不可用其他域名的证据替代。
4. **DNS证据**：本地解析链、上游类别、是否经过VPS、bootstrap/私有域例外及失败回退。只有 `resolv.conf` 或DNS成功不能满足。
5. **地区一致性**：多来源德国归属、ASN/数据中心属性、冲突记录、与真实目标路线的关系。不得公布真实节点地址；原始证据限本地受控位置。
6. **时区语言**：IANA时区、当日DST/偏移、系统绝对时间正常；服务内有效TZ/locale及浏览器语言。只取允许字段，不打印全部环境或系统服务认证参数。
7. **应用表面**：中立本地页确认时区/语言、WebRTC/定位权限和无直接回退；保留现有profile，必要时对比少量字段，不宣称检查一次覆盖全部浏览器或Electron应用。
8. **普通原生程序**：使用隔离合成TCP/UDP/DNS探针确认不依赖环境变量的路径按矩阵成功代理或拒绝；不通过启动目标应用充当探针。
9. **旁路清单**：Windows interop、其他回环代理、宿主DNS、容器/daemon、WSLg/共享目录明确属于已约束、允许例外或未验收。
10. **生命周期**：配置重生、登录/休眠/重启与上游不可用时的拒绝直连，必须在隔离环境或已有经验证独立关键联网通路时测试。不能停共享核心、切DNS或禁网卡给用户注入故障。

### 6.2 明确的状态判定

- **通过（限定范围）**：每个必测项有新鲜证据，入口和配置可持久，所有声明例外已获认可；只对该Scope与该次测试条件下结论负责。
- **失败关闭**：代理或DNS不可用时请求失败、未转为直连。它是保护行为，但不等于业务可用；不能把 Windows 无法访问校园/API 或 WSL 无法访问其获准公网业务也包装成完整功能成功。WSL 校园访问不在需求范围内。
- **失败/停止**：关键URL异常、未授权直连、DNS回退、本机公网出口出现在应代理通路、地区冲突、协议绕过、入口失效或启动窗口开放。停止扩大变更，只定向撤回本轮已确认原因并复验。
- **未知/未验收**：WSL未启动、应用不能运行、只读源码推断、某协议缺证据、当前路由已变化。必须保留未知，不用“应该”充当通过。
- **本地地址仍存在**：在仅声明代理出口的Scope N中属预期，不自动失败；若用户要求更强本地信息隔离，则需要Scope H/另一架构，不能伪造命令修饰结果。

## 7. 不可保证项、资料保护与下一步决策

不可保证：完整复刻VPS内核/硬件、所有命令只显示公网出口、统一所有GeoIP/ASN库、消除账号与cookie历史、改变所有TLS/HTTP指纹、应用绝不主动上传本机字段、抵御拥有相同/更高权限的主体、任意网络与所有启动瞬间绝对零泄漏，以及任何服务的区域/风控接受。

必须保留浏览器/Claude profiles、keyring、字体、输入法、工作区、现有账号与资料；不删除或重置以追求“干净身份”。不操作CC Switch数据库与备份。迁移前针对本次对象备份，回退仅撤销本轮对象，不恢复早期全量网络快照。

后续应由主会话收敛三个决定：

1. 是否采用“固定VPS出口 + 尚不支持流量拒绝”作为可选临时过渡，以及如何完成 R02 要求的透明 TCP/UDP 均成功经 VPS。过渡不替代最终目标；只有用户明确改需求才可降低最终范围。ICMP 等额外 L3 协议是否要求成功转发另行确定。
2. 保留Windows互操作与共享便利并接受宿主信息可见，还是另行授权更强隔离及其可用性代价。
3. 以隐私和可解释一致性为目标，不以“完整复刻/绕过风控”为验收；地区未知或冲突时停止相关受限访问，不通过扩大检测寻求放行。
